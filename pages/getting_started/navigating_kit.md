The support-kit helps research communities apply the EOSC EDEN preservation framework in practice. Every module answers one concrete need, written as a user story: *as a [role], I want to [task], so that [reason]*.

## 1. Start from your role

The kit has three learning paths. Pick the one closest to your work:

- **[Researchers](researchers)**: you produce data and deposit it with a repository.
- **[Repository managers](repository_managers)**: you run the services and processes that keep deposited data trustworthy.
- **[RDM trainers](rdm_trainers)**: you teach others how to preserve research data.

Each role page lists its modules in a suggested order. The sidebar shows where you are, and every module links to the next one.

## 2. Or start from what you want to do

The [home page](/) lists every module as a user story. Filter by role or by kind of guidance, or click a Core Preservation Process to see only the modules that apply it.

## 3. Know what kind of page you're reading

Each module is one of four kinds, following the [Diátaxis](https://diataxis.fr) model:

| Kind | Use it when you want to… |
|---|---|
| Tutorial | learn by doing, the first time |
| How-to | reach a specific goal |
| Reference | look something up |
| Explanation | understand the background and the why |

## 4. Follow the links to the framework

Modules are anchored to the 30 [Core Preservation Processes](cpps) defined by EOSC EDEN WP1, and to certification and FAIR [frameworks](frameworks) such as CoreTrustSeal, the nestor Seal and ISO 16363. Each module shows both what it cites itself and how WP1 maps its processes.

## 5. Use the checklists

Recommendations are written as checklists. Print a module to work through it with your team; the navigation is left out of the printout.

## 6. Help improve the kit

Every page has buttons to **edit it** or **open an issue** on GitHub. Modules marked *Draft* are especially open to feedback.
