{%- comment -%} Interactive walkthrough of how a module gets into the kit: Google Doc → ready folder → hourly workflow → pull request → site. Self-contained: markup here, styles under .kit-flow in _custom_classes.scss. Used on pages/contribute.md. {%- endcomment -%}
    Main path Fix loop: back to the author Review loop: changes go into the Doc

    What authors need

    • A copy of EDEN Support-kit – module template
    • Access to the folder EDEN Support-kit – ready for the kit
    • Nothing else: no GitHub account, no Markdown, no scripts. A plain table filled in your own words; process names work as well as numbers

    What runs in the repository

    • gdocs-to-pr.yml: hourly at :17, or run by hand with one Doc link
    • gdoc_to_module.py: metadata table → front matter, cleans the export
    • check_modules.py (reports, never blocks) and make_sidebar.py: run before every site build

    One-time setup (repository admin)

    1. Google service account with the Drive API on
    2. Share the folder with it as Commenter
    3. GitHub secret GDRIVE_SA_KEY, variable GDRIVE_READY_FOLDER
    4. Allow Actions to open pull requests; optional KIT_BOT_TOKEN so builds run on them
